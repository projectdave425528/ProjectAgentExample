Kiro的Credit計算法是否根據文件數量,定Token數量?

### Kiro 完整回覆
根據 Kiro 官方資料，Credit 係按 prompt 嘅**複雜度（complexity）**計算，唔係按文件數量。

核心機制：
- 最小單位 0.01 credit，按複雜度浮動
- 簡單 prompt < 1 credit，複雜 prompt > 1 credit
- Auto = 1x，Sonnet 4 = 1.3x
- 所有操作都消耗 credit（Vibe/Spec/hook execution）

同 Token 嘅關係：
- Credit 係複雜度嘅抽象單位，背後同 token 用量有關
- Kiro 加咗 optimization（caching、intent detection、model routing）
- Steering files 大小會影響 credit（always-on 每次載入 = 增加 input tokens = 增加複雜度）

對 Steering 設計嘅影響：Steering 越長 → input tokens 越多 → credit 越高。之前評分報告估算嘅「每次慳 8,000-10,000 tokens」≈ 慳 0.1-0.3 credit/次。
