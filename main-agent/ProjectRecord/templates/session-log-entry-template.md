# Session Log Entry Template

> 所有 Agent（Root / Main / Sub）記錄 Session 時必須遵守此格式。
> 每段對話一個 entry，追加到 session 文件尾部。

---

## 格式

```markdown
## [YYYY-MM-DD HH:MM:SS] 對話記錄

### 用戶輸入
[用戶完整的輸入內容]
- 唔包括 HOOK_INSTRUCTION 標籤內容
- 如果用戶附帶圖片/文件，標注「（附件：{檔名}）」

### 決策過程（思考鏈）
1. {收到咩類型嘅請求 → 點樣理解用戶意圖}
2. {考慮過咩方案 → 點解揀呢個方案}
3. {遇到咩問題 → 點樣解決}
4. {最終決策同原因}

### Kiro 回覆摘要
[2-5 句話總結回覆重點，唔係完整回覆]
- 做咗咩（結果）
- 提供咗咩建議（如果有）
- 問咗用戶咩（如果有）

### 工具調用 + 操作
| # | 操作 | 目標 | 結果 |
|---|------|------|------|
| 1 | {工具名/操作類型} | {參數/目標文件} | {一句話結果} |
| 2 | ... | ... | ... |

### 文件變動
| 類型 | 路徑 | 備註 |
|------|------|------|
| 建立 | {path} | {用途} |
| 修改 | {path} | {改咗咩} |
| 刪除 | {path} | {原因} |

---
```

## 欄位說明

| 欄位 | 必填？ | 說明 |
|------|:---:|------|
| 時間戳 | ✅ | `Get-Date -Format 'yyyy-MM-dd HH:mm:ss'` 本地時間 |
| 用戶輸入 | ✅ | 完整內容，唔刪減 |
| 決策過程 | ✅ | 3-5 步，每步一句話，重點係「點解」 |
| Kiro 回覆摘要 | ✅ | 2-5 句總結（唔係完整回覆） |
| 工具調用 + 操作 | ⚠️ | 有調用工具時填，純問答寫「無工具調用」 |
| 文件變動 | ⚠️ | 有建立/修改/刪除文件時填，冇就省略 |

## 同舊格式嘅差異

| 舊格式問題 | 新格式改善 |
|-----------|-----------|
| 「Kiro 完整回覆」太長 | 改為「回覆摘要」2-5 句 |
| 「工具調用」+「執行操作」重疊 | 合併為一個 table |
| 純問答時表格冗餘 | 冇工具調用就寫一句「無工具調用」 |
| 冇記錄文件變動 | 新增「文件變動」section |
| 決策過程 + 回覆重複邏輯 | 決策過程記「點解」，回覆摘要記「做咗咩」 |

## 純問答簡短版

如果對話係純問答/解釋/教學（冇任何工具調用或文件操作），可以用簡短版：

```markdown
## [YYYY-MM-DD HH:MM:SS] 對話記錄

### 用戶輸入
{問題}

### 決策過程（思考鏈）
1. {理解}
2. {判斷}

### Kiro 回覆摘要
{2-3 句總結}

---
```

## 路徑規則

| 條件 | 路徑 |
|------|------|
| 涉及特定 Project | `main-agent/ProjectRecord/{active-project}/UserConfig/sessions/` |
| 通用對話 | `UserConfig/sessions/` |
| 唔確定 | 預設 `UserConfig/sessions/` |

## 文件命名

- 格式：`YYYY-MM-DD-session-HHMM.md`
- HHMM = 本 session 第一條訊息嘅時間
- 同名文件已存在 → 追加（同一個 chat window）

## 優先級

已有同名文件存在嘅路徑 > active-project 路徑 > 頂層路徑
